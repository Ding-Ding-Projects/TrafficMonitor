# Offline documentation companion

The companion bundles the same complete static documentation output as the hosted documentation, including its article and wiki inventory, task navigation, search, settings and local assets. It supplements the hosted documentation and does not replace the native MFC application or its Squirrel installer.

Run `build.bat --docs-companion -Version 1.0.0` or `build-installer.bat --docs-companion -Version 1.0.0`. Both produce `artifacts/docs-companion/TrafficMonitor-Documentation-1.0.0-x64.exe`, a single unsigned portable executable. The portable launcher extracts its own embedded runtime to temporary storage. No adjacent runtime directory, separate installer, administrator access or network connection is needed to launch the packaged reader. Its local reading preferences use a dedicated application profile. Delete that profile through the operating system when full local preference removal is needed.

The build obtains pinned Node 24.10.0 through the existing hash-verified documentation bootstrap, restores the companion npm lockfile with lifecycle scripts disabled, and uses the official runtime download and builder checksum verification. Runtime version 45.0.0 and builder 26.15.3 are pinned. Build acquisition needs network access on a cold cache; reading the finished bundle does not. Production rebuilds the documentation and rejects output whose receipt does not match HEAD. Each file has an offline inventory hash, and the executable has a separate source/version/hash manifest and checksum file.

The renderer uses a secure, standard custom origin with sandboxing, context isolation and no Node integration, preload bridge or IPC. Only bundled paths under `/TrafficMonitor/` resolve. Malformed paths, traversal, foreign origins, permissions, downloads, webviews and new windows are blocked. A restrictive content security policy and request filter block external resources. External source and download links remain visible for provenance but cannot leave the offline reader. Use the hosted documentation for those destinations. No credential or personal-wording payload is bundled.

The release job retains the existing native `Setup.exe`, `RELEASES` and full package. After that normal release exists, the documentation job builds the companion from the same source and attaches its four uniquely named outputs to that same tag. It checks normal-release state, source, hash and asset readback, and never overwrites an existing asset or creates another release. A companion build or upload failure remains a failed documentation job; it does not relabel a native-only release as complete.

Packaging is not runtime verification. The output manifest explicitly marks runtime verification pending. Source provenance, complete bundled article inventory and local hashes do not prove interaction, accessibility, layout, persistence, installed update behavior or completion of the wider required-feature inventory. Existing missing-image records and staged feature states remain unchanged.
